# Phase 05 - Chat and Commerce UX

## Goal
Make messaging stable, useful, and clear for buyer-seller conversations while also supporting self-chat as a private notes space.

## Current Chat Architecture
- Room path: `chat_rooms/{roomId}`.
- Messages path: `chat_rooms/{roomId}/messages/{messageId}`.
- Room ID is generated by sorting UIDs.
- Self-chat uses one unique participant ID.
- Chat images upload to Cloudinary, not Firebase Storage.
- Chat list and room UI live in `lib/screens/chat_screen.dart`.
- Chat service lives in `lib/services/chat_service.dart`.

## Scope
Improve:
- Chat list stability.
- Chat search.
- Self-chat.
- Message send reliability.
- Image message upload states.
- Read receipts and timestamps.
- Profile-to-chat navigation.
- Commerce-friendly actions where useful.

## Non-Goals
- Do not add full payments or checkout.
- Do not add Firebase Storage.
- Do not add complicated offer contracts before basic chat is stable.
- Do not reintroduce canned quick-message chips in post detail unless approved.

## Required Behavior
1. Chat list.
   - Shows current profile name/avatar for the peer when available.
   - Does not flash cached rooms and then disappear.
   - Supports long-press delete with confirmation.
   - Delete hides the chat for the current user only.
   - Search filters by peer display name.
   - Search current user's name shows self-chat.

2. Chat room.
   - Android back returns to chat list when opened from Messages tab.
   - Back button pops the route when opened from public profile.
   - Header avatar/name opens public profile for the peer.
   - Self-chat should not crash and should show the current user's profile.
   - Text messages send with local pending state.
   - Failed messages show failure state.
   - Image upload shows progress or pending feedback.

3. Message model.
   - Keep fields explicit:
     - `id`
     - `senderId`
     - `senderEmail`
     - `receiverId`
     - `text`
     - `imageUrl`
     - `timestamp`
     - `isRead`
     - `type`
     - delivery/read maps
     - `clientNonce`
   - Use `FieldValue.serverTimestamp()` for persisted timestamps.

4. Read state.
   - Current user's sent messages show sent/read status.
   - Opening a room marks received messages as read.
   - Self-chat should not produce misleading unread badges.

## Optional Commerce v1
Only after base chat is stable:
- Add a lightweight `offer` message type.
- Offer message fields:
  - `amount`
  - `currency`
  - `postId`
  - `status`: `pending`, `accepted`, `declined`, `countered`
- Keep UI minimal and avoid checkout/payment claims.

## Firestore Rule Requirements
- Chat room create allows one participant for self-chat and two for normal chat.
- Only participants can read/update a room.
- Only participants can read/create messages.
- Sender ID must match `request.auth.uid` for new messages.

## Acceptance Criteria
- Sending text works consistently.
- Sending image works or fails gracefully.
- Chat list search works.
- Self-chat works from chat search and own public profile.
- Public profile chat opens without Material ancestor errors.
- Android back behavior is correct in tab and route contexts.
- `flutter analyze` and `flutter test` pass.
